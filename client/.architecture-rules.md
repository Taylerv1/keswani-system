# .architecture-rules.md
Feature-Driven Structure Rules (Copilot Guidance)

Copilot must follow these rules for any file creation, modification, refactor, or backend/frontend integration.

## 1. Top-Level Structure (Mandatory)

```text
client/
├── app/                # Routing layer only
├── features/           # Domain modules (logic + UI per feature)
├── components/         # Shared UI + shared layout only
├── lib/                # Shared logic (api client, helpers, translation, hooks)
├── providers/          # Global providers
├── translations/       # i18n dictionaries
├── mocks/
├── public/
└── styles/
```

## 2. Feature Folder Rules

Every domain/section/module must live under:

```text
client/features/<domain>/<subdomain>/
```

Allowed files inside each feature:

```text
components/        # UI for this feature only
api.ts             # Frontend API client for this feature
hooks.ts           # All feature hooks
utils.ts           # All feature utilities
types.ts           # Feature/domain types
index.ts           # Barrel export
<FeatureName>Page.tsx  # Main orchestration screen
```

Nothing else is allowed unless explicitly required.

## 3. app/ Folder Rules (Routing Only)

Inside `/app/`, allowed files are:

- `page.tsx`
- `layout.tsx`
- `loading.tsx`
- `error.tsx`
- `not-found.tsx`
- `template.tsx`
- `app/api/**/route.ts` (Next.js route handlers only)

Rules:

- No business logic in `app/**`
- No data hooks in `app/**`
- No API call orchestration in `app/**`
- Route pages must wrap/import screens from `features/**`

Example:

```typescript
import { PropertyPage } from "@/features/rent/properties";
export default PropertyPage;
```

## 4. Feature Page Rules (Important)

Inside each feature, the screen file must be named exactly:

```text
<FeatureName>Page.tsx
```

This is the only file allowed to orchestrate:

- state wiring
- hooks wiring
- modal composition
- table/card composition
- UI-level filtering/pagination

Forbidden nested folders unless explicitly requested:

- `pages/`
- `views/`
- `screens/`

## 5. Prohibited Patterns (Strict)

Copilot must not create these folders automatically:

```text
forms/
view/
views/
screens/
table/
tables/
modals/
state/
reducers/
context/
```

Unless explicitly requested.

## 6. Naming Conventions

### Components

- PascalCase
- Must reflect domain entity
- Examples: `PropertyTable`, `PropertyCreateModal`, `PropertyMobileCard`

### Hooks

- Must be inside `hooks.ts`
- Example: `export function usePropertyState() {}`

### API

- Always named `api.ts`

### Utilities

- Always named `utils.ts`

### Domain Types

- Always named `types.ts`

### Main Page File

- `PropertyPage.tsx`, `TenantPage.tsx`, `MeterPage.tsx`, etc.

## 7. Shared Components Rules

```text
components/
  ui/       # Buttons, inputs, cards, icons...
  layout/   # AdminLayout, CustomerLayout, sidebars...
  shared/   # Reusable functional components across domains
```

Rules:

- No business rules in shared components
- No feature-specific API calls in shared components

## 8. API Layer Rules

### Client-side (frontend domain calls)

```text
features/<domain>/<subdomain>/api.ts
```

### Next.js route handlers (proxy/backend boundary)

```text
app/api/<resource>/route.ts
```

Copilot must not mix both layers.

## 9. Hooks Rules

All hooks for one feature should be consolidated inside one file:

```text
hooks.ts
```

Do not create multiple hook files unless:

- the file is too large to maintain, or
- explicitly requested by the team.

## 10. Utils Rules

Store feature utilities in one file:

```text
utils.ts
```

Do not split into multiple utility files unless:

- `utils.ts` exceeds 500 lines, or
- utilities clearly belong to independent domains.

## 11. Types Rules

Types must be defined in:

```text
types.ts
```

Then re-exported from:

```text
index.ts
```

## 12. Import Boundary Rules (Mandatory)

- `app/**` may import from `features/**`, `components/**`, `lib/**`, `providers/**`
- `features/**` may import from:
  - same feature
  - `components/ui`, `components/layout`, `components/shared`
  - `lib/**`, `translations/**`
- `components/**` must not import feature-specific modules
- Cross-feature direct imports are discouraged; prefer each feature's `index.ts`

## 13. Testing Location Rules

Preferred test placement:

```text
features/<domain>/<subdomain>/__tests__/
```

Or co-located:

```text
*.test.ts / *.test.tsx
```

Tests should follow the same feature boundaries.

## 14. Exception Policy

If a rule must be broken, include a short code comment or PR note with:

- reason
- scope
- planned cleanup

No silent exceptions.

## 15. Enforcement Checklist (CI/Review)

- Enforce with ESLint import restrictions
- Enforce structure checks in CI (script or lint rule)
- Block merges that violate boundaries without documented exception

## Canonical Feature Template

```text
features/rent/properties/
  PropertyPage.tsx
  api.ts
  hooks.ts
  utils.ts
  types.ts
  index.ts
  components/
    PropertyCreateModal.tsx
    PropertyEditModal.tsx
    PropertyDeleteModal.tsx
    PropertyTable.tsx
    PropertyTableRow.tsx
    PropertyMobileCard.tsx
```

Copilot must follow this structure for all modules.

## Summary Table

| Layer | Location | Allowed | Not Allowed |
|-------|----------|---------|-------------|
| Routes | `app/**` | Routing files, wrappers, Next route handlers | Business logic, feature state orchestration |
| Features | `features/<domain>/<subdomain>/` | Domain page, hooks, utils, types, API, feature components | Shared-only concerns |
| Feature Page | `<FeatureName>Page.tsx` | Orchestration and composition | Extra nested page/view/screen folders |
| Shared Components | `components/` | Reusable UI/layout/shared blocks | Domain business rules and feature API logic |
| API | `features/**/api.ts` + `app/api/**/route.ts` | Frontend calls + proxy boundary | Mixing layers |
| Hooks | `features/**/hooks.ts` | Consolidated feature hooks | Scattered hook files without reason |
| Utils | `features/**/utils.ts` | Consolidated feature utils | Unnecessary utility fragmentation |
| Types | `features/**/types.ts` | Canonical feature types + barrel exports | Scattered domain types |
